# CLAUDE-10: Performance, release architecture and independent evidence standard

Read-only wave. Nothing was edited, committed, published or deployed. I could not run Rojo, Luau or Studio here (`rojo`, `selene`, `luau` and `stylua` are not on PATH). Every runtime claim below is marked NOT TESTED.

## 1. Findings

**F1. The performance gate checks a JSON flag, not performance.**
- `tools/v06/roblox-perf/check-budgets.mjs` reads `avatar-memory-budget.json` and exits 1 only if `fabricatedLiveFpsClaims !== false`.
- The "budgets" (60 FPS desktop, 30 FPS mobile, 20 plot parts, 1024x1024 textures) are not compared against anything in the place.
- `runtimeProfilingStatus` is a hard-coded string, `STATIC_BUDGETS_VERIFIED_LIVE_DEVICE_CAPTURE_BLOCKED_ON_LINUX_ARM64`, and its "STATIC_BUDGETS_VERIFIED" part has no evidence behind it.
- The honest "no fake FPS" intent is good. The "verified" wording is not.

**F2. The Roblox build is not in the main CI workflow.**
- `.github/workflows/ci.yml` runs validate, compile, web and minecraft builds, vitest and the mcaddon check. It never runs `build:roblox` or Rojo.
- `ci-v04.yml` showed no `rojo` or `roblox` matches in the lines I grepped; I did not read it in full.
- The release report `reports/v06/independent-release/INDEPENDENT_RELEASE_REVIEW.md` claims `build:roblox` PASS, but nothing in the checked-in CI reproduces that.

**F3. The Roblox build depends on a gitignored generated file.**
- `SessionManager.init` requires `ReplicatedStorage.Shared.Packs` (`apps/roblox/src/server/Core/SessionManager.luau`).
- `Packs.luau` is generated by `tools/compiler/roblox.ts` and listed in `.gitignore` line 8.
- A clean checkout that runs only `rojo build` therefore yields a place that fails at server start. This has not been run, so it is NOT TESTED.

**F4. The release manifest points at paths the build does not produce.**
- `tools/v12/release/release-manifest-v12.json` lists `dist/roblox/MiraVerse.rbxl`.
- `package.json` `build:roblox` writes `apps/roblox/dist/miraverse.rbxlx`.
- `tools/v12/release/verify-release-gate.mjs` only checks that 6 source files exist. It does not check the binary, hashes or the manifest paths.
- The manifest's `generated_at` is `2026-11-04T07:48:05Z` and it carries no content hashes.

**F5. `KnowledgeV12.luau` is 200 KB and 3,306 lines, and nothing at runtime uses it.**
- It sits in `ReplicatedStorage.Shared`, so any module that requires it would ship the whole table to every client.
- I did not find a `require` of it in `apps/roblox/src`. My grep for the name failed on a shell glob error and I did not redo it. Re-run it before relying on this.
- It is also a published, child-facing file with contested claims inside it (for example `claimStatus = "disputed"`). That makes the cultural review in section 5 a release blocker.

**F6. Persistence is memory-only, yet the release docs imply versioned saves.**
- `PlayerDataStoreService.luau` uses an in-memory table and has no DataStore calls.
- `SessionManager.luau` says "No DataStore".
- Passport stamps are lost when a player leaves.
- Progression-persistence budgets (DataStore request limits, session locking) have nothing to measure yet.

**F7. The place builds many parts at server start, and challenges clean up through per-session folders.**
- `MapBuilder.luau` (495 lines) calls `Instance.new` 23 times in source, inside loops over 5 countries. The final instance count is unknown.
- `StreamingEnabled = true` is set in `default.project.json`. There is no `StreamingMinRadius`, `StreamingTargetRadius` or model streaming mode, so the defaults apply. Whether it helps is NOT TESTED.
- `Challenges/init.luau` creates `ChallengeRemotes` lazily and `session.folder` per challenge. `Gather.luau` connects `Touched`. I did not verify that every connection is disconnected, so leaks are NOT TESTED.
- Server-side rate limiting exists (a 0.25 s cooldown per remote in `SessionManager.luau`, which also validates the `Say` index), and `PlayerRemoving` cleans up. These are a good base.

**F8. Evidence honesty is mixed.**
- Good: `RobloxLaunchPage.tsx` shows `STAGING_UNPUBLISHED_HUMAN_APPROVAL_REQUIRED` and a null Place ID. `reports/v12/RELEASE_READINESS.md` lists Roblox Studio smoke tests as `NOT_RUN_ON_LINUX_AARCH64_HOST`.
- Bad: that same file's executive summary says "READY FOR STAGED RELEASE (50 / 50 ... Completed & Verified)". The "Present & Verified" labels are file-existence checks.
- The Roblox performance check and the release gate are both weaker than their names suggest.
- Prior reports were written by the producing swarm and self-attested. Examples: `reports/v06/independent-release/` is one short file, and `reports/v08/PERFORMANCE.md` measures the web only.

**F9. Existing tests are structural.**
- `tests/roblox/roblox-v04.test.ts` checks the Rojo config and that no Stripe strings appear in Luau.
- `tools/v06/luau-checks/check-luau.mjs` checks that three directories exist and greps for a forbidden URL. It does not parse Luau.

**F10. Dead and duplicate code may add weight.**
- `Foundation/WorldBootstrap`, `QuestEngine`, `Building`, `Social`, `NPCs`, `Activities` and `Systems/SocialAvatar` are not required from `Main.server.luau`, which loads only `MapBuilder` and `SessionManager`.
- I did not confirm that nothing else requires them. They may be unreachable, which would mean bytes shipped with no function.

## 2. Specification

### 2.1 Performance budgets (to be enforced)

The numbers below are proposed targets, not measured values. The 60 and 30 FPS figures come from `avatar-memory-budget.json`; the rest are my proposals for human sign-off.

| Metric | Proposed budget | Enforced by |
|---|---|---|
| Server `Instance` count at start (descendants of Workspace) | ≤ 5,000 total and ≤ 1,200 per country | static count of `Instance.new` and the built rbxlx |
| Parts per player plot | ≤ 20 (existing) | static test plus Studio probe |
| Unanchored parts at rest | 0 outside challenges | static scan for `Anchored = false` |
| Replicated Luau bytes (`Shared`) | ≤ 100 KB per client-required module | build step |
| `KnowledgeV12` shipped to client | 0 bytes; serve per-country slices from the server on demand | design change |
| Heartbeat loops or `while true` in client scripts | 0 unbudgeted | static grep |
| Texture size | ≤ 1024x1024 (existing) | asset audit |
| Server frame time | ≤ 16.6 ms at 10 players | Studio MicroProfiler |
| Client FPS | ≥ 60 desktop, ≥ 30 low-end mobile | device capture |
| Remote calls | ≤ 4 per second per player (the existing 0.25 s cooldown) | already in code |

Runtime rows (the last four) are NOT TESTED and may only be filled from device captures.

Design changes:
- Make streaming explicit with `StreamingEnabled`, `StreamingMinRadius` and `StreamingTargetRadius`. Build each country world lazily at selection time, rather than all five at boot.
- Disconnect every challenge connection when `session.done` is set.

### 2.2 Release architecture

One canonical artifact path, one manifest, and a reproducible build.

1. **Artifact:** `apps/roblox/dist/miraverse.rbxlx` from `npm run build:roblox`. Fix the manifest paths (F4).
2. **Order:** `npm run compile` (generates `Packs.luau` and `KnowledgeV12`) → `rojo build`. Make `build:roblox` depend on compile (F3).
3. **CI job `roblox-build`:** install a pinned Rojo (the release checklist says 7.7.1). Run Luau analysis with `luau-analyze` or selene. Run the static budget checks. Upload the rbxlx and its sha256. This also closes F2.
4. **Release manifest v2** with these fields: git SHA, tool versions, artifact paths with sha256 and byte size, content-pack hash, per-gate result (`PASS`, `FAIL`, `NOT_TESTED` or `BLOCKED_HUMAN`), and evidence file paths. A gate result of `PASS` is permitted only if the evidence file exists and its hash matches.
5. **Gate states:** `STAGING_UNPUBLISHED_HUMAN_APPROVAL_REQUIRED` stays the default. Publishing needs a signed approval record. Never invent a Place or Universe ID.
6. **Rollback:** keep the previous rbxlx hash in the manifest. Keep the DataStore schema version `mv.roblox.save.v6` and require a migration test before any bump.
7. **Persistence:** if DataStore is wired in later, add `UpdateAsync` with session locking and a `BindToClose` flush, plus a budget test for request counts. That work belongs to another worker's scope; I list it only as a dependency.

### 2.3 Independent evidence standard

An independent reviewer is someone who did not author the code or the gate under review.

- **E1. Independent reproduction:** a clean checkout runs the documented commands. The captured output is stored with the commit SHA and `NODE_VERSION`. Self-reported "PASS" lines don't count.
- **E2. Evidence classes:**
  - `STATIC`: what the build and linters can prove.
  - `STUDIO_RUNTIME`: Studio Play-test logs and screenshots, recorded by a human or the Studio MCP tools on macOS or Windows.
  - `DEVICE`: captures from real phone, tablet and desktop.
  - `HUMAN_REVIEW`: named reviewer, date, scope and decision.
- **E3. Forbidden claims:** any "works", "smooth" or "FPS" statement without a `STUDIO_RUNTIME` or `DEVICE` record. The existing `fabricatedLiveFpsClaims` flag is replaced by a check that scans the reports for claim words.
- **E4. Playtest script (to be run by a human on macOS or Windows; all of it NOT TESTED):**
  - Select each of the 5 countries.
  - Complete the 5 challenges.
  - Confirm one stamp per chapter and no double award.
  - Leave and rejoin. Memory-only state is expected to reset; record that as known behaviour.
  - Fire the remotes with bad inputs.
  - Capture MicroProfiler, server and client memory, and instance count.
- **E5. Child-safety checks to record:** chat is disabled (`Main.client.luau` disables TextChatService and CoreGui chat) and communication is the 4 fixed phrases only. These need runtime confirmation.
- **E6. Review sign-off:** the review file lists every gate with its state. Any `NOT_TESTED` or `BLOCKED_HUMAN` item keeps the release at "staged, not publishable".
