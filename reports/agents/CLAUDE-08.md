# CLAUDE-08: Multilingual content architecture for 14 locales

Nothing was edited, committed or deployed. Nothing was run, so every runtime behaviour is **NOT TESTED**. I had no Studio access.

## 1. Findings

**F1. The 14 locales exist only in the Minecraft global catalog.**
- `swarm/minecraft-global/catalog-data.mjs:15-29` defines `GLOBAL_LOCALES`: en-US, fr-FR, fr-CA, de-DE, zh-Hans-CN, ja-JP, ru-RU, uk-UA, ko-KR, ar, ar-LB, ar-IQ, ar-EG, ar-MA.
- Each entry has `script`, `direction`, `fallbackChain` and `isNativeBedrock`.
- Nothing in the Roblox tree consumes this list.

**F2. The web and content layers support only 6 locales.**
- `packages/content/schema.ts:1-6` has `Lang` = ar-LB, ar-EG, ar-IQ, ko, fr, en. It also holds `RTL`, `UI_LANGS` and `STORY_LANGS`.
- `content/localization/v06/locale-matrix.json` lists the same 6, with the status `PENDING_FINAL_REVIEW`.
- `tools/validate.ts:769` hard-fails a release unless there are exactly 6 locale files.
- Code mismatch: the web uses `fr`, `ko` and `ar-LB`, while the Minecraft catalog uses `fr-FR`, `ko-KR` and `ar-LB`. Locale IDs are not normalised anywhere. The Minecraft audit fixture uses a third form, `ar_LB`, in `apps/minecraft/tests/fixtures/locales/bedrock-locales-audit.json`.

**F3. Roblox has no localization layer.**
- A grep for `LocalizationService`, `Translator` and `LocaleId` in `apps/roblox` found nothing.
- The only locale logic is a hard-coded RTL check on three Arabic codes in `apps/roblox/src/client/Presentation/NativeQuestHud.luau:7`. Its banner string is English-only and uses `string.format`.
- Inline English strings:
  - `apps/roblox/src/shared/Challenges/Word.luau`: "Find the word for:", "Not that one. Try again!".
  - `apps/roblox/src/shared/Challenges/init.luau:314`: `challenge.goal_en or title_en`.
  - `apps/roblox/src/client/ChallengeHud.client.luau`: writes server-sent text straight to `goalLabel.Text` and `detailLabel.Text`.
- Mentor greetings are hard-coded as `greetingEn` and `greetingNative` pairs in `apps/roblox/src/server/NPCs/MentorDialogueService.luau:6-57`, for the 5 countries only.
- `apps/roblox/src/client/UI.luau` uses `Enum.Font.FredokaOne` and `GothamMedium`. I did not check Arabic, Hangul, CJK or Cyrillic glyph coverage for these fonts; that needs Studio.

**F4. Content is "en plus one native string".** There is no per-locale map.
- Pack challenges use `title_en` and `goal_en` (`packages/content/schema.ts:62-73`).
- Quests use `titleEn`/`titleNative` and `labelEn`/`labelNative` (`content/quests/LB.json`).
- Dialogue uses `textNative`, `textTranslit` and `textEn` (`content/dialogue/LB.json`).
- Some `labelNative` values just repeat the English text (for example "Wheat Flour" in `content/quests/LB.json`). That is a defect.
- Only the 5 home-country languages have a "native" field, so adding DE, CN, JP, RU, UA, MA or fr-CA needs a new shape.

**F5. KnowledgeV12 is a generated file with a good model for layered content.**
- `apps/roblox/src/shared/KnowledgeV12.luau` is generated by `tools/v12/compiler/compile-v12.mjs` and marked DO NOT EDIT.
- Each entry has `claimStatus`, `confidence`, `knowledgeClass` and `ageExplanations` for 5-7, 8-10, 11-13 and 14-17. All text is English.
- `content/v12/epistemology/EPISTEMIC_POLICY.md` defines neutral labels such as "Historical Record (Corroborated)" and "Mythology & Sacred Narrative". Those labels need translating.
- Localized knowledge text must be keyed by entry `id` plus age tier, and must carry over `claimStatus`.
- Some English data already contains defects that translation would multiply. Examples are a stray Chinese fragment "农번기" in a 14-17 entry (around line 345) and the typo `externally_corrobated` as a `claimStatus` value. Both need an English-source fix before translation.

**F6. Review state is uniformly unreviewed.**
- `humanNativeSpeakerSignoffStatus: PENDING_FINAL_REVIEW` in `content/localization/v06/locale-matrix.json`.
- `reviewStatus: PENDING_NATIVE_HUMAN_REVIEW` in the drafts and in `content/vocab/enriched/*.json`.
- `review_status: draft_ai_pending_native_review` in `content/v12/locales/ar-LB/lebanese-dialect-qa.json`.
- `content/v12/locales/fr-ko/fr-ko-localization.json` embeds raw LLM output (a `dgx_spark_metrics.content` block). That text is untrusted and unreviewed, and it contradicts the file's own glossary. For example, it gives the *traboule* etymology as "Old French *trabouler*", while the glossary says Latin *transambulare*. It must not be used as a source.
- `content/locales/drafts/*.json` hold only 11 UI keys each, but `validateLocaleData` requires at least 25 keys (`tools/validate.ts:629`). Either the web locale files hold the fuller set or validation is out of sync. I did not reconcile them.

**F7. A register policy already exists.**
- `reports/v12/LOCALIZATION_REVIEW.md` says historical figures never use modern slang, contemporary mentors use regional dialect, and ancient Phoenician is distinct from ar-LB.
- Implementation should encode this as a per-string `register` field.

**F8. Existing scope limits.** Roblox is wired for 5 countries (LB, EG, IQ, KR, FR). The Minecraft catalog defines 11. The other 6 (DE, CN, JP, RU, UA, MA) have no Roblox content or packs, so 9 of the 14 locales have no cultural source in the repo.

## 2. Specification

### 2.1 Locale registry (single source of truth)
- Create `content/localization/v14/locales.json`, derived from `GLOBAL_LOCALES`. The 14 canonical IDs are BCP-47 style.
- Fields per locale: `id`, `name`, `nativeName` (human-reviewed), `script`, `dir`, `fallbackChain`, `status` (`baseline` | `draft` | `reviewed`), `robloxLocaleId` (nullable), `reviewer` (nullable), and an `aliases` list.
- `aliases` maps the legacy IDs: `fr` to `fr-FR`, `ko` to `ko-KR`, `en` to `en-US`, `ar_LB` to `ar-LB`, and so on.
- Add a `normalizeLocale()` function in one shared module and use it everywhere.
- `RTL` is derived from `dir`, never hard-coded. The `NativeQuestHud.luau:7` check is replaced by a registry lookup.
- `ar` (MSA) is the shared parent for the 4 Arabic variants. `fr-FR` is the parent of `fr-CA`.
- Fallback rule: a missing key resolves along the `fallbackChain`, then to `en-US`. The English fallback is logged as a missing key and counted. It is never shown silently in a release build.

### 2.2 String catalog format
- One file per locale and domain: `content/localization/v14/strings/<locale>/<domain>.json`.
- Domains: `ui`, `hud`, `challenge`, `dialogue`, `quest`, `knowledge`, `vocab`, `epistemic`, `stamps`.
- Entry shape, keyed by a stable ID (for example `challenge.LB.<id>.goal`, `knowledge.EG-KB-HIST-FANOUS-COMPETING-ORIGINS.5-7`):

  `{ "text": "...", "register": "contemporary|historical|neutral", "ageTier": "5-7|...", "reviewStatus": "ai_draft|human_reviewed|approved", "reviewer": null, "sourceHash": "<hash of en-US source>", "maxChars": 0 }`

- `sourceHash` marks translations stale when the English changes.
- `en-US` is authoritative. Translation never edits `claimStatus`.
- Placeholders use `{name}` only. Plural and gender forms use an ICU-style `{count, plural, ...}` subset. Arabic needs 6 plural categories and the other target languages need fewer.
- Home-country languages keep a separate `native` field (existing `textNative` and `labelNative`), so the old shape still compiles.

### 2.3 Roblox runtime
- New shared module `Localization.luau` (in `apps/roblox/src/shared/`, mapped into ReplicatedStorage.Shared by `apps/roblox/default.project.json`), with `Localization.t(key, params)` and `Localization.dir()`.
- A compiler step (extending `tools/v12/compiler/compile-v12.mjs`) emits one Luau module per locale and domain, in the same GENERATED style as `KnowledgeV12.luau`.
- Load only the active locale plus `en-US`, to limit memory.
- Locale selection order: an explicit in-game language choice, then `LocalizationService` / `Player.LocaleId` mapped through `robloxLocaleId`, then `en-US`.
- The 4 Arabic dialects and `ar-MA` are not Roblox player locales as far as the repo shows. Whether Roblox exposes `ar-LB` and similar IDs is **unverified (NOT TESTED)**. So a visible language picker must exist, and an Arabic Roblox locale maps to `ar` by default.
- The server sends keys plus params, not display text. This changes `ctx.notify` in `apps/roblox/src/shared/Challenges/init.luau`, `Word.luau`, and the `ChallengeHud` text handler. The client resolves the key.
- RTL: set `TextXAlignment` and layout direction from `dir`. Mixed Latin and Arabic strings (like the bidi vectors in the Minecraft audit fixture) need isolation marks.
- Fonts per script (Arabic, CJK, Cyrillic, Latin) need a font fallback table. Glyph coverage is **NOT TESTED**.
- Child privacy: store the chosen language only as part of the existing profile. No new tracking, and nothing leaves the player's data.

### 2.4 Build and validation gates
- Extend `tools/validate.ts`:
  - Replace the "exactly 6 files" rule (`:769`) with a registry-driven rule.
  - Every locale must have every key in the `en-US` key set, or be listed as `fallback_ok` in the registry.
  - Check placeholder parity, and check `maxChars`.
  - Check that `claimStatus` and age tiers are identical across locales.
  - Check that no locale is `approved` without a named reviewer.
  - Check that the shipped locale set for the Roblox release is explicit.
- Release gate: a locale is user-selectable only when its core domains (`ui`, `hud`, `challenge`, `dialogue`) are `human_reviewed`. Other locales show the English fallback with a visible "draft" marker, or stay hidden.
- The AI-draft marker is a build-time property, not a runtime claim. Dialect copy always needs native review. The Minecraft audit already says `humanReviewRequiredForDialectCopy: true`.

### 2.5 Content scope per locale
- **Tier 1 (content exists today):** en-US, fr-FR, ko-KR, ar-LB, ar-EG, ar-IQ. The existing packs, dialogue, quests and vocab need migrating into the new catalog, with sources preserved.
- **Tier 2 (UI and system strings only):** ar, fr-CA, de-DE, zh-Hans-CN, ja-JP, ru-RU, uk-UA, ar-MA. Roblox has no cultural content for DE, CN, JP, RU, UA or MA yet (F8).
- No story, quest, vocab or knowledge text for Tier 2 may be written until the relevant cultural source and a reviewer exist.

### 2.6 Rollout order
1. Registry plus `normalizeLocale` plus a Luau `Localization` module, with `en-US` only.
2. Replace the inline English strings listed in F3 with keys.
3. Compile and migrate the 6 Tier 1 locales.
4. Validation gates.
5. Language picker UI.
6. Tier 2 locales, as reviewers become available.

## 4. Dependencies

- Another wave must decide the Roblox ship set. This is a registry flag only.
- Content workers' English source IDs (quests, dialogue, knowledge) must be stable. Keys depend on them.
- A font and typography decision for Roblox UI (Arabic, CJK, Cyrillic).
- The epistemic policy labels (`content/v12/epistemology/EPISTEMIC_POLICY.md`) need translation, and this must go to the same reviewers.
- Reviewer sign-off per locale (see section 5).

## 5. Open gaps (human review or runtime proof needed)

1. **Native reviewers.** None are named in any file for any locale. Every existing translation, dialect term, transliteration and vocab entry is `PENDING_NATIVE_HUMAN_REVIEW`, so none can be treated as correct. Specific examples that need checking:
   - the ar-LB, ar-EG and ar-IQ vocab and dialect terms in `content/v12/locales/*` and `content/vocab/enriched/*`;
   - the ar-EG vocab entry for "grandmother";
   - the transliterations in `content/dialogue/*.json`.
2. **Tier 2 cultural content.** No repo source exists for DE, CN, JP, RU, UA or MA in Roblox. Their places, literature, legends, festivals and foods must come from a human-curated source list. I did not invent any. Each item must be tagged real place, literature or legend, using the `knowledgeClass` and epistemic labels.
3. **Fix English defects before translation:** the stray Chinese fragment "农번기" and the `externally_corrobated` typo (see F5), plus the placeholder `labelNative` values (F4). The raw LLM block in `fr-ko-localization.json` should be quarantined, not used.
4. **Locale-count conflict.** `tools/validate.ts` requires exactly 6 locales for release. Either the 14-locale target is staged, or that rule changes. Needs a product decision.
5. **Roblox locale mapping.** Which of the 14 map to a native Roblox locale ID is unverified. Check Roblox's supported-languages documentation; I did not.
6. **NOT TESTED at runtime:**
   - RTL layout and bidi text in Roblox UI.
   - Font glyph coverage for Arabic, CJK and Cyrillic.
   - Text overflow with longer strings (German, Russian).
   - `Player.LocaleId` behaviour.
   - Memory impact of per-locale modules.
   - Chat and text-filter interaction (static strings are not filtered, but any player-entered text is).
7. **Translations themselves.** None are authored in this wave. Machine drafts, if used, must keep `reviewStatus: ai_draft` and stay hidden or marked until a reviewer approves them.
8. **Age tiers.** Should the 4 age tiers apply to all 14 locales, or only the knowledge domain? Untested assumption: knowledge only.
